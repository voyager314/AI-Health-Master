## Why

运动模块已经能记、能看、能改，体重页却还是占位页。`body_metric` 表、`measured_at` 索引与只读 Repository 都已就位，但没有任何一条写入路径。

本 change 交付 PRD **v0.1** 的体重模块：一键记录、近 12 周周均趋势、同日多条的当日取值与明细。增肌期体重按月变化，单日读数被水分波动淹没，周均才是判断增重节奏的读数（US-05）；它也是 v0.4 周复盘里「周均体重斜率」与看板里「体重记录天数」的数据来源。v0.1 的出口标准要求断网时能记录运动**与体重**，缺了这一块 v0.1 无法收尾。

## What Changes

覆盖 PRD v0.5 的 FR-W01、FR-W02、FR-W04 与 §10.3 的 `weight_add` 埋点。纯前端，不碰 `backend/`。

- **快速记录体重**（FR-W01）：体重页底部的记录入口带出上一条的数值，kg 显示下每次 ±0.1 kg，斤显示下每次 ±0.2 斤（同为 0.1 kg），点一次即保存。存储统一为 kg，且落在 0.1 kg 网格上；斤只是显示换算，单位选择不落库。测量时刻由程序写入。
- **周均体重趋势**（FR-W02）：自绘 SVG，画近 12 个自然周的周均折线，叠加每日的当日值散点。周均按有效日计算：有效日不足 3 天的周没有周均点，折线在此断开；本周不足 3 天时提示「本周数据太少」。
- **同日多次记录与明细**（FR-W04）：同一天允许多条，当日值取测量时刻最晚的一条；图表下方按日列出近 12 周的全部记录，并标出当日取值。
- **修改与删除**（FR-W04.1，PRD 增补）：点明细中的一条进入编辑页，只能改数值；删除为软删除，须二次确认。
- **新增命令**：`body_metric/record`、`body_metric/update`、`body_metric/remove`，全部登记进 `COMMANDS`。
- **新增领域纯函数**：0.1 kg 网格规整、kg 与斤的换算、当日取值、按有效日计算周均。按自然日分组的函数从运动模块提为通用函数，两个模块共用一份。
- **时间窗口扩展**：近 N 个自然周的区间与各周的周标识、两个自然日相差的天数。周界算术仍只在 `stats/timeWindow` 一处。
- **新增埋点**：`weight_add`，只记预填值的使用情况与保存时的显示单位，不记体重数值。
- **数据契约收紧**：`body_metric.weight_kg` 必须落在 0.1 kg 网格上，写入与导入共用这一条校验；补齐 `BodyMetric` 各字段的注释。
- **修正运动编辑页的日期显示**（FR-T07.1）：页面上原有的日期取自 `logged_at` 的前 10 个字符，那是 UTC 日期，旁边却是本地时刻。东八区本地 00:00–08:00 写入的记录会显示成前一天的日期。改为按记录自带的时区偏移取自然日，与列表的分组口径一致。
- **存储结构不变**：不新增字段、不新增表，`schema_version` 保持 1，本 change 不写迁移。

## Capabilities

### New Capabilities

- `weight-tracking`：体重的记录、周均趋势、当日取值与明细、修改与删除。包括数值网格与单位换算、预填与步进、12 周窗口、周均的有效日口径，以及数据不足时怎么呈现。

### Modified Capabilities

- `local-data-store`：新增 `body_metric` 的字段契约——测量时刻由程序写入、用户不可编辑；体重以 kg 存储，限定在 0.1 kg 网格上，离网格的值在写入与导入时都被拒绝。
- `local-telemetry`：接入 `weight_add` 及其属性定义。
- `workout-logging`：新增 FR-T07.1——编辑页展示的训练日期必须是记录写入时所在的那个自然日，与列表的分组口径一致；修正原先按 UTC 日期展示的问题。

## Impact

**代码范围**：只动 `frontend/`。`backend/` 不触碰。

| 区域 | 影响 |
|---|---|
| `frontend/src/entities/` | 改。`BodyMetric` 补齐字段注释；`weight_kg` 增加 0.1 kg 网格校验，取值范围提成常量，供界面与命令共用；写入失败原因的枚举移到这里，存储层与共享组件引用同一份 |
| `frontend/src/stats/timeWindow.ts` | 扩展。近 N 个自然周的区间与周标识序列、两个自然日相差的天数 |
| `frontend/src/domain/` | 新增 `bodyMetric.ts`：网格规整、kg 与斤换算、当日取值、周均。按自然日分组从 `workoutLog.ts` 提为通用函数 |
| `frontend/src/commands/` | 新增 `bodyMetric.ts`，三条命令登记进 `COMMANDS`；按幂等键定位记录的函数提为运动与体重共用 |
| `frontend/src/telemetry/`、`storage/telemetry.ts` | 改。登记 `weight_add` |
| `frontend/src/features/weight/` | 新增。体重页、编辑页、数值步进输入、趋势图 |
| `frontend/src/features/workout/` | 改。改用通用分组函数、共享的保存失败提示与日期标签；编辑页的训练日期改为按记录自带的偏移展示，这是本 change 唯一一处运动模块的行为变更 |
| `frontend/src/shared/` | 新增保存失败提示组件与日期标签函数：都从运动模块中提出，运动与体重共用 |
| `frontend/src/app/routes.tsx` | 改。`/weight` 换成真实页面，新增 `/weight/:id` |
| `frontend/package.json` | **无新增依赖**。趋势图自绘 SVG，不引图表库、日期库或表单库 |

**对既有测试的影响**：运动列表与分组函数的测试随通用化调整写法，断言不弱化。约束自检（写入口单一、`user_id` 注入、日界与周界算术唯一）、往返一致性、路由外壳测试都要覆盖新页面与新命令；这些测试本身就是验收依据。

## 与 PRD 原文的差异（留痕）

| 项 | PRD 原文 | 本 change 的处理 | 依据 |
|---|---|---|---|
| 周均的计数口径 | FR-W02 与术语表：当周有效**记录** ≥ 3 条才计算 | 按有效**日**计：先按 FR-W04 取每天的当日值，再对有记录的那些天求平均；有效日 ≥ 3 才计算 | 按条数计，一天称三次就够数了，周均会被单日的水分波动主导，正好违背用周均抵消日波动的初衷。PRD 的验收例（72.0 / 72.4 / 72.6 → 72.3）在三条分属三天时照样成立 |
| FR-W04 的版本 | §7.6 列为 v0.4（Should） | 随本 change 在 v0.1 交付 | 按有效日算周均，前提是有当日取值；修改与删除也需要明细作入口。缺了它，FR-W02 无法定义 |
| 斤的步进 | FR-W01：±0.1 步进 | kg 下 ±0.1 kg，斤下 ±0.2 斤 | 存储网格是 0.1 kg，正好是 0.2 斤。按 0.1 斤步进时，一半的取值在保存后会被规整成相邻值，用户会看到自己输入的数字变了 |
| 「保留一位小数」落在哪一层 | FR-W01：保留一位小数 | 落成字段契约：`weight_kg` 必须在 0.1 kg 网格上，写入与导入都校验。界面在提交前规整，命令层拒绝离网格的值，不替调用方取整 | 只在显示时取整，存储值与显示值就会不一致：导出文件里是 72.45，界面上却是 72.5 |
| 周均的显示精度 | 未规定 | 周均先规整到 0.1 kg，再换算成斤（72.33 → 72.3 kg → 144.6 斤） | 两种单位的显示必须能互相换算。先换算再取整会得到 144.7 斤，对不上 72.3 kg |
| 测量时刻 | 未规定能否编辑 | 程序写入、只读；修改只改数值 | 与运动记录的提交时刻同一条规则。允许改时刻，记录就能跨日、跨周移动，悄悄改写用户已经看过的周均 |
| 单位切换的范围 | 单位默认 kg，可切斤 | 单位只在一次查看里有效：带入编辑页，返回时再带回，不落库；从导航重新进入或重开应用都回到 kg | 不改数据模型。持久化留给设置页 |
| 记录的修改与删除 | 体重需求中没有这一项 | 增补 FR-W04.1：明细中可改数值、可删除（软删除，二次确认） | 输错的体重（把 72.4 敲成 27.4）如果改不了，会一直拉偏所在那一周的周均；三条命令也需要界面入口 |
| 明细的范围 | FR-W04：历史全部保留可查 | 界面上的明细覆盖近 12 周；更早的记录留在库中并随导出带出 | 体重页的窗口就是 12 周趋势，明细与图表用同一个窗口。体重不受保留期清理，记录不会丢失 |
| 快速记录的位置 | §15.1-D：页面上方 | 吸附在屏幕底部，位于屏幕下三分之一 | 可用性基线（FR-S03.5）要求核心操作单手可达。放在顶部的话，图表与明细一长，就要先滚回顶部才够得到 |
| `weight_add` 的属性 | 是否修改预填值 | 预填值状态分三态（无预填 / 未改 / 已改），另加保存时的显示单位 | 首次记录没有预填值，布尔值表达不了这种情况；单位的分布用来判断单位偏好值不值得持久化 |

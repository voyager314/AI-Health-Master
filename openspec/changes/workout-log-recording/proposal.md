## Why

数据地基已经就位：6 张业务表、Repository 与 Command 层、导出导入、PWA 外壳、告知同意全部落地，但应用里没有任何一条业务记录可写。`workout_log` 能存、能导出、能往返，界面却是占位页。

本 change 交付 PRD **v0.1** 的运动模块：手动记录、近 30 天查看、查阅更早、编辑与删除。这是产品唯一的生存理由——「练完说一句话就记完了」——的手动版，也是语音版（v0.2）在录音失败时的兜底入口。没有它，v0.1 的出口标准「自己连续使用 2 周」无从开始，`指标填充率`与`周运动记录达标率`两个指标也无数据可算。

## What Changes

覆盖 PRD v0.5 的 FR-T01、FR-T05、FR-T06、FR-T07 与 §10.3 的四个埋点事件。纯前端，不碰 `backend/`。

- **手动记录今日运动**（FR-T01）：一页内新增多张项目卡片。每张卡片含项目名（必填，≤40 字，自由输入）、组数、每组次数、重量（kg，0.5 步进）、描述（≤200 字），除项目名外均可留空。提交生成一条记录，`logged_at` 由程序写入设备本地时刻（精确到秒），用户不参与。卡片只呈现已填写的指标，未填项不显示占位符或默认值。
- **近 30 天记录查看**（FR-T05）：从底部导航进入运动模块直接落在列表页。按自然日分组，组内按时间倒序；每天显示记录条数与项目名摘要。30 天为含今天的 30 个自然日，按设备本地时区计算。
- **查阅更早与保留期**（FR-T06）：列表底部提供「查看更早」，可扩到 60、90、180 天；超过 180 个自然日的记录在应用启动时物理删除。
- **记录编辑与删除**（FR-T07）：已保存记录可改卡片与描述、可整条删除。删除为软删除，导出时排除。
- **新增命令**：`workout_log/create`、`workout_log/update`、`workout_log/remove`、`workout_log/purge_expired`，全部登记进 `COMMANDS`。
- **新增领域纯函数**：按自然日分组、每日摘要、一条记录已填指标数（0-3，供填充率统计）。入参为记录数组，不读存储。
- **新增埋点事件**：`record_save`、`item_add`、`item_remove`、`history_expand`，属性只记结构化值与区间值。
- **Repository 新增物理删除能力**：按主键集合删除，只服务于保留期清理。
- **存储结构不变**：不新增字段、不新增表，`schema_version` 保持 1，本 change 不写迁移。

## Capabilities

### New Capabilities

- `workout-logging`：运动记录的建立、查看、编辑与删除——项目卡片的字段规则、提交时刻与来源、30 天列表的分组与排序、查看更早的展开层级、180 天保留期的清理时机。

### Modified Capabilities

- `local-data-store`：物理删除的例外清单落成实现——保留期清理按主键集合删除，且只删 `logged_at` 早于保留期窗口的记录；`workout_log` 的保留期不再是纸面规则。
- `storage-access-layer`：Repository 契约新增按主键集合物理删除的方法，并限定其唯一用途。
- `local-telemetry`：接入上述四个事件及其属性定义。

## Impact

**代码范围**：只动 `frontend/`。`backend/` 不触碰。

| 区域 | 影响 |
|---|---|
| `frontend/src/entities/` | 不改。`WorkoutLog` / `WorkoutItem` 与项目卡片规格在数据层对齐时已经定义 |
| `frontend/src/storage/repositories/types.ts` | 改。新增 `purge(ids)`，只经 `storage/internal` 暴露给命令层 |
| `frontend/src/storage/indexeddb/repository.ts` | 改。实现 `purge`，在事务句柄上按主键批量删除 |
| `frontend/src/commands/` | 新增 `workoutLog.ts`，四条命令登记进 `COMMANDS` |

| `frontend/src/stats/timeWindow.ts` | 扩展。新增「以某时刻为终点、跨度 N 个自然日」的区间与保留期截止时刻，日界算术仍只在这里实现 |
| `frontend/src/features/workout/` | 新增。列表页、卡片表单、编辑页、卡片组件、删除与保存失败的提示 |
| `frontend/src/app/routes.tsx` | 改。`/workout` 换成真实列表页，新增 `/workout/new` 与 `/workout/:id` |

| `frontend/src/telemetry/` | 改。新增四个事件的登记与属性 |
| `frontend/package.json` | **无新增依赖**。表单与列表都用现有 React，不引表单库、日期库或状态管理库 |

**对既有测试的影响**：约束自检（写入口单一、`user_id` 注入）、往返一致性、路由外壳测试都要覆盖新页面与新命令；这些测试本身是验收依据，不能因改动而弱化。

## 与 PRD 原文的差异（留痕）

| 项 | PRD 原文 | 本 change 的处理 | 依据 |
|---|---|---|---|
| 保留期清理的删除方式 | §10.5 约束 5 只允许「清空全部数据」物理删除，§10.2 又要求启动时清理超期记录 | 按 §10.2 实现物理删除，并在 `local-data-store` 的例外清单中与「清空」「图片清理」并列登记 | 两条规则直接冲突。软删除在这里没有意义：超期记录既不进列表也不进导出，留下墓碑只是让库无限增长，而这正是保留期要防的事 |
| 「查看更早」的分层 | FR-T06 只要求「可展开至 180 天」，§10.3 的 `history_expand` 又按 30/60/90/180 记录展开到的天数 | 展开按 30 → 60 → 90 → 180 四档递进，每档一个按钮 | 两处描述必须能对上，否则埋点的「已展开到的天数」没有确定的取值集合 |
| 提交时刻不可编辑 | FR-T01 规定时间点由程序写入、用户不参与；FR-T07 允许编辑记录 | 编辑页只改卡片与描述，`logged_at` 只读 | 时间点是记录的事实。允许改它会让「今天练的」变成「昨天练的」，周统计随之漂移，而用户无法预期这种漂移 |
| 同日多条不设当日值 | FR-W04 定义了体重的「当日取最后一条」，运动记录未定义 | 同一天的多条记录各自独立展示，不合并、不取代表值 | 早练与晚练是两件事，不是同一次测量的两次读数。合并会丢掉其中一次的训练内容 |
| 空记录不允许提交 | PRD 未直接规定 | 至少一张卡片且项目名有值才可提交；删除最后一张卡片时保存按钮置灰 | 一条没有任何项目的记录无法显示、无法统计，等于给用户制造了一条看不见的脏数据 |
| 重复提交 | §12 第 10 条要求「按钮节流 + 以 UUID 去重」 | 提交按钮在写入期间禁用；`client_id` 作为幂等键，同一 `client_id` 不产生第二条记录 | 这两条是 §12 明确要求的，不需要新决策，但需要在命令层落地，否则连点两次就会产生两条一模一样的记录 |

## ADDED Requirements

### Requirement: 运动记录的埋点事件

运动模块必须（SHALL）记录下列四个事件，属性只允许结构化值与区间值，禁止采集自由文本、项目名、备注内容与具体重量次数。

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `record_save` | 保存一条记录 | `input_source`、项目数、已填指标数（0-3）、耗时 |
| `item_add` | 新增一张卡片 | 操作后该记录的卡片数 |
| `item_remove` | 删除一张卡片 | 操作后该记录的卡片数 |
| `history_expand` | 点「查看更早」 | 已展开到的天数（30/60/90/180） |

「已填指标数」指这条记录里有几张卡片至少填了组数、次数、重量中的一项，取值 0 到项目数之间；它与指标填充率的分子口径一致。

埋点失败不得影响保存、编辑与删除：写入与否由业务结果决定，与统计是否成功无关。

#### Scenario: 保存后记录一条事件
- **GIVEN** 用户保存了一条含 2 张卡片、其中 1 张填了指标的记录
- **WHEN** 保存成功
- **THEN** 产生一条 `record_save` 事件
- **AND** 属性含项目数 2、已填指标数 1、`input_source` 为 `manual`

#### Scenario: 增删卡片各自记录一条
- **GIVEN** 用户在录入页添加一张卡片
- **WHEN** 操作完成
- **THEN** 产生一条 `item_add` 事件，属性为操作后的卡片数
- **AND** 删除一张卡片时同理产生 `item_remove`

#### Scenario: 展开记录的是目标天数
- **GIVEN** 列表当前展示近 30 天
- **WHEN** 用户点击「查看更早」展开到 60 天
- **THEN** 产生一条 `history_expand` 事件，属性为 60

#### Scenario: 属性不含自由文本与具体数值
- **GIVEN** 一条运动记录的项目名为「右肩不舒服的卧推」，备注写了一段话
- **WHEN** 检查保存后产生的事件属性
- **THEN** 属性中不含项目名、备注内容、具体重量或次数的值

#### Scenario: 埋点失败不影响保存
- **GIVEN** 埋点写入失败
- **WHEN** 用户保存一条记录
- **THEN** 记录正常保存
- **AND** 界面不出现任何错误提示

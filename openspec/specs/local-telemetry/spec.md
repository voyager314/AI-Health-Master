## Purpose

提供本地埋点机制，让产品决策能基于真实使用数据而非感觉——PRD 的每一版都有「至少能看到什么」的指标要求，而这些指标的原始事件必须从第一版就开始积累，事后补埋会丢掉整段历史。本能力只负责记录机制与隐私约束；具体事件随各自功能所属的 change 接入，指标看板留到 v0.4。
## Requirements
### Requirement: 本地埋点记录机制

应用必须（SHALL）提供统一的埋点记录接口，把事件写入 `analytics_event` store。事件必须含事件名、发生时刻（UTC ISO 8601 + `tz_offset_minutes`）与结构化属性。

本期埋点只在本地记录，禁止上报到任何服务端。事件数据随全量 JSON 导出一并带出，供离线统计使用。

#### Scenario: 事件写入本地
- **GIVEN** 一个已注册的埋点事件被触发
- **WHEN** 记录完成
- **THEN** `analytics_event` 中新增一条含事件名、时刻与属性的记录

#### Scenario: 埋点不外发
- **GIVEN** 应用记录了若干埋点事件
- **WHEN** 检查应用发出的全部网络请求
- **THEN** 不存在任何上报埋点的请求

#### Scenario: 事件随导出带出
- **GIVEN** `analytics_event` 中存在事件记录
- **WHEN** 用户导出全量 JSON
- **THEN** 导出文件中含这些事件记录

### Requirement: 埋点的隐私约束

埋点属性只允许记录结构化值与区间值。禁止采集：用户输入的自由文本、图片内容或图片引用、语音转写文本、设备标识、位置信息，以及任何可识别自然人的身份信息。

数值类属性若可能反映身体数据（如体重、容量），必须（SHALL）以区间而非精确值记录。

#### Scenario: 不采集自由文本与图片
- **GIVEN** 全部埋点事件的属性定义
- **WHEN** 检查其字段
- **THEN** 不含自由文本、图片内容、图片引用或语音转写文本字段

#### Scenario: 不采集身份与位置
- **GIVEN** 全部埋点事件的属性定义
- **WHEN** 检查其字段
- **THEN** 不含设备标识、位置信息或任何可识别自然人的身份信息

#### Scenario: 身体数据以区间记录
- **GIVEN** 一个记录训练容量的埋点事件
- **WHEN** 检查其属性值
- **THEN** 容量以区间形式记录，而非精确数值

### Requirement: 埋点失败不影响业务

埋点记录失败禁止影响任何业务操作：业务写入必须（SHALL）照常成功，界面禁止因埋点失败而报错或阻断。

#### Scenario: 埋点失败业务照常
- **GIVEN** `analytics_event` 写入因存储异常而失败
- **WHEN** 用户正在进行一次业务写入
- **THEN** 业务写入照常成功
- **AND** 界面不展示任何错误

### Requirement: 基础埋点事件

应用必须（SHALL）接入下列 3 个事件；其余事件随对应功能一并接入。

| 事件 | 触发时机 | 属性 |
| --- | --- | --- |
| `app_open` | 应用打开 | 是否以 PWA 独立窗口启动、是否首次使用 |
| `export` | 导出完成 | 导出格式（json/csv）、逐表记录条数 |
| `clear_data` | 清空完成 | 清空前的逐表记录条数 |

#### Scenario: 记录应用打开
- **GIVEN** 用户打开应用
- **WHEN** 应用完成加载
- **THEN** 记录一条 `app_open` 事件，含是否 PWA 启动与是否首次使用

#### Scenario: 记录导出
- **GIVEN** 用户完成一次 JSON 导出
- **WHEN** 导出结束
- **THEN** 记录一条 `export` 事件，格式为 `json`，含逐表记录条数

#### Scenario: 记录清空
- **GIVEN** 用户确认并完成清空全部数据
- **WHEN** 清空结束
- **THEN** 在已清空的 `analytics_event` 中写入一条 `clear_data` 事件，含清空前的逐表记录条数
- **AND** 该事件是清空后 `analytics_event` 中唯一的记录（它在清空之后写入，而非豁免于清空）

### Requirement: 运动记录的埋点事件

运动模块必须（SHALL）记录下列四个事件，属性只允许结构化值与区间值，禁止采集自由文本、项目名、备注内容与具体重量次数。

| 事件 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `record_save` | 保存一条记录 | `input_source`、项目数、已填指标数（0-3）、耗时 |
| `item_add` | 新增一张卡片 | 操作后该记录的卡片数 |
| `item_remove` | 删除一张卡片 | 操作后该记录的卡片数 |
| `history_expand` | 点「查看更早」 | 已展开到的天数（30/60/90/180） |

「已填指标数」指这条记录中三项基础指标的**种类数**：组数、每组次数、重量各自只要有任意一张卡片填了值就算已填，取值 0-3。它不随卡片数量增长——同一指标在多张卡片上出现仍只算一项。指标填充率只看这个值是否大于 0。

埋点失败不得影响保存、编辑与删除：写入与否由业务结果决定，与统计是否成功无关。

#### Scenario: 保存后记录一条事件
- **GIVEN** 用户保存了一条含 2 张卡片的记录，一张填了组数与次数，另一张只填了重量
- **WHEN** 保存成功
- **THEN** 产生一条 `record_save` 事件
- **AND** 属性含项目数 2、已填指标数 3、`input_source` 为 `manual`

#### Scenario: 指标种类数不随卡片数量增长
- **GIVEN** 一条记录有 4 张卡片，每张都填了重量但没有组数与次数
- **WHEN** 保存成功
- **THEN** `record_save` 的已填指标数为 1

#### Scenario: 三项全空时为 0
- **GIVEN** 一条记录的每张卡片都只填了项目名
- **WHEN** 保存成功
- **THEN** `record_save` 的已填指标数为 0

#### Scenario: 增删卡片各自记录一条
- **GIVEN** 用户在录入页添加一张卡片
- **WHEN** 操作完成
- **THEN** 产生一条 `item_add` 事件，属性为操作后的卡片数
- **AND** 删除一张卡片时同理产生 `item_remove`

#### Scenario: 展开记录的是目标天数
- **GIVEN** 列表当前展示近 30 天
- **WHEN** 用户点击「查看更早」展开到 60 天
- **THEN** 产生一条 `history_expand` 事件，属性为 60

#### Scenario: 属性不含自由文本与具体数值
- **GIVEN** 一条运动记录的项目名为「右肩不舒服的卧推」，备注写了一段话
- **WHEN** 检查保存后产生的事件属性
- **THEN** 属性中不含项目名、备注内容、具体重量或次数的值

#### Scenario: 埋点失败不影响保存
- **GIVEN** 埋点写入失败
- **WHEN** 用户保存一条记录
- **THEN** 记录正常保存
- **AND** 界面不出现任何错误提示
